# アクセス解析のセットアップ

サイト内でアクセス数と滞在時間を確認できる仕組みです。Cloudflare D1（データベース）に自前で記録し、
管理者用ページ `/maroinudayo/` で集計を見られます。記事ごとの閲覧数は記事一覧と記事ページに公開表示されます。

Cloudflare のダッシュボードを開かなくても、サイト上で数字が確認できます。

## 構成

| ファイル                                 | 役割                                                   |
| ---------------------------------------- | ------------------------------------------------------ |
| `functions/api/view.js`                  | ページ表示を1件記録する（POST）                        |
| `functions/api/duration.js`              | ページの滞在秒数を加算する（POST）                     |
| `functions/api/article-views.js`         | 記事ごとの累計を返す（公開・GET）                      |
| `functions/api/stats.js`                 | 管理者向けの集計を返す（パスワード必須・GET）          |
| `src/components/ViewTracker.tsx`         | 全ページで表示を記録するクライアント側の処理           |
| `src/components/StatsDashboard.tsx`      | `/maroinudayo/` の画面                                 |
| `db/schema.sql`                          | D1 のテーブル定義                                      |
| `db/migrations/001-add-duration.sql`     | 滞在時間の列を後から足す場合の差分                     |
| `db/migrations/002-add-visit-events.sql` | 流入元・デバイス・時間帯のテーブルを足す差分           |
| `db/migrations/003-add-daily-visits.sql` | サイト全体の訪問者数・セッション数のテーブルを足す差分 |
| `src/components/stats/`                  | グラフ部品（外部ライブラリ不使用のインラインSVG）      |

## 保存するもの・しないもの

保存するのは「どのパスが、どの日に、何回表示され、合計で何秒見られたか」だけです。
IP アドレス・ユーザーエージェント・Cookie など、個人を特定できる情報は一切保存しません。

### 指標の定義

| 指標         | 意味                       | 数え方                                     |
| ------------ | -------------------------- | ------------------------------------------ |
| 表示回数     | ページが開かれた回数（PV） | ページを開くたびに1。再読み込みも数える    |
| 訪問者数     | サイトに来た人の数（UU）   | ブラウザ×日で1回だけ。**パスに紐づけない** |
| セッション数 | タブのセッション数         | タブのセッションごとに1回だけ              |
| 閲覧者数     | そのページを見た人の数     | ブラウザ×日×パスで1回だけ                  |

**閲覧者数を合計しても訪問者数にはなりません。** 1人が3ページ見ると、閲覧者数は
各ページで1ずつ計上されて合計3になりますが、訪問者数は1人のままです。
そのため、サイト全体の訪問者数は `daily_visits` テーブルに別で持っています。

`page_views` テーブル（パス × 日）:

- `views` … 表示回数
- `visitors` … 閲覧者数（そのページを見た人の数）
- `total_seconds` … 滞在秒数の合計
- `duration_samples` … 滞在時間を測れた回数。平均はこの数で割ります

`daily_visits` テーブル（日）:

- `visitors` … サイト全体の訪問者数
- `sessions` … セッション数

`visit_events` テーブルには、日 × 時間帯 × デバイス × 流入元 ごとの表示回数を記録します。

- 時間帯 … サーバ側で日本時間に換算した 0〜23 時
- デバイス … 画面幅から desktop / tablet / mobile を判定（UA文字列は解析しません）
- 流入元 … リファラの**ホスト名まで**。URL全体は個人の閲覧履歴に近づくため保存しません

ブラウザを変えたり、ストレージを消したりすると別人として数えられます。厳密な実人数ではなく目安です。

### 滞在時間の測り方

タブが**手前に表示されている間だけ**を加算します。裏に回している時間や、別ウィンドウを見ている時間は数えません。
タブを開きっぱなしにされても平均が壊れないようにするためです。

- ページを離れる直前に `sendBeacon` で送るので、閉じても記録が残ります
- 1秒未満は「開いた瞬間に閉じた」とみなして送りません
- 1回の送信で加算できるのは最大30分までです（異常値対策）
- ブラウザが強制終了した場合など、送信が届かないこともあります。そのぶんは
  `duration_samples` にも数えないので、平均値は歪みません

## 手順

### 1. D1 データベースを作る

Cloudflare ダッシュボード → **Storage & Databases → D1** → **Create database**

- 名前: `maro-analytics`（任意）

### 2. テーブルを作る

作成した D1 の **Console** タブを開き、`db/schema.sql` の中身をそのまま貼り付けて実行します。

すでにテーブルを作ってある場合は、足りないぶんだけ差分を実行してください。

- 滞在時間の列が無い → `db/migrations/001-add-duration.sql`
- `visit_events` テーブルが無い → `db/migrations/002-add-visit-events.sql`
- `daily_visits` テーブルが無い → `db/migrations/003-add-daily-visits.sql`

どちらも未実行でも表示回数と滞在時間は記録され続けます。

- `visit_events` が無い → 「流入元」「デバイス」「時間帯」「曜日 × 時間帯」の4パネルが案内文になります
- `daily_visits` が無い → 訪問者数の統計タイルと推移の訪問者数の線が出ません

wrangler を使う場合は次のコマンドでも同じことができます。

```bash
npx wrangler d1 execute maro-analytics --remote --file=db/schema.sql
```

### 3. Pages プロジェクトにバインドする

Cloudflare ダッシュボード → **Workers & Pages → maroinu → Settings → Bindings**

**D1 database binding** を追加します。

| 項目          | 値               |
| ------------- | ---------------- |
| Variable name | `DB`             |
| D1 database   | `maro-analytics` |

設定するのは **Production のみ**です。変数名は必ず `DB` です（コードがこの名前を見ています）。

本番は `maroinu.pages.dev`（master ブランチのデプロイ）です。Preview にも同じ D1 を割り当てると、
動作確認やブランチのプレビューで開いたぶんが本番の数字に混ざってしまうため、割り当てません。
Preview 側は D1 が無い状態になり、記録がスキップされるだけでページは通常どおり動きます。

プレビューでも計測を試したい場合は、`maro-analytics-preview` のような別の D1 を作って
Preview にだけ割り当ててください。

### 4. 統計ページのパスワードを設定する

同じ **Settings → Environment variables** で、**Secret** として追加します。

| 項目          | 値               |
| ------------- | ---------------- |
| Variable name | `STATS_PASSWORD` |
| Value         | 任意のパスワード |

これも **Production** に設定します（Preview で `/maroinudayo/` を開きたい場合は Preview にも）。
このパスワードを知っている人だけが `/maroinudayo/` の数字を見られます。総当たり対策として、
同じ IP からの認証失敗が5分間に10回を超えると一時的に拒否します。

### 5. 反映する

バインドと環境変数を変えただけでは既存のデプロイには反映されません。再デプロイが必要です。

```bash
gh workflow run cloudflare-pages.yml --ref master
```

### 6. 動作確認

1. サイトのページをいくつか開く
2. `https://maroinu.pages.dev/maroinudayo/` を開き、設定したパスワードを入力
3. 表示回数が入っていれば成功

滞在時間は、ページを数十秒開いてから**別のページに移動するかタブを閉じる**と記録されます。
開いたままでは送信されないので、確認するときは一度離れてください。

記事ごとの閲覧数は `/api/article-views` を60秒キャッシュしているため、
記事一覧に反映されるまで最大1分ほどかかります。

## 統計ページで見られるもの

| パネル                 | 内容                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------ |
| 累計表示回数           | 公開してからの合計                                                                   |
| 統計タイル4枚          | 表示回数 / 訪問者数 / 平均滞在時間 / 1人あたり表示回数。前期間比とスパークライン付き |
| ページ別の閲覧者数     | 「数値の表も見る」で確認できます。訪問者数とは別物です                               |
| 推移                   | 日別の表示回数と訪問者数。カーソルを合わせるとその日の数字が出ます                   |
| よく見られたページ     | 期間内の表示回数上位10件                                                             |
| じっくり読まれたページ | 平均滞在時間が長い順。表示回数の多さとは別の観点                                     |
| 曜日ごとの平均表示回数 | 期間内の各曜日の平均                                                                 |
| 流入元                 | どこ経由で来たか                                                                     |
| デバイス               | パソコン / スマートフォン / タブレット                                               |
| 時間帯                 | 日本時間の時間帯別                                                                   |
| 曜日 × 時間帯          | 濃いところがよく見られている時間。告知を出す時間帯の目安                             |

期間は 7日 / 30日 / 90日 を切り替えられます。
「数値の表も見る」を押すとグラフと同じ内容を表で確認できます。

## 無料枠について

D1 の無料枠は 1日あたり読み取り500万行・書き込み10万行です。
1ページ表示あたりの書き込みは、表示の記録と滞在時間の記録で2回程度です。
タブを何度も出し入れすると滞在時間の送信が増えますが、それでも通常の運用で上限に達することはありません。

## 未設定でも壊れないようになっています

`DB` バインドが無い状態でもサイトは通常どおり表示されます。
その場合は記録がスキップされ、閲覧数の表示が出ないだけです。
`/maroinudayo/` はデータベース未設定である旨のメッセージを表示します。

## ローカルで試す場合

`next dev` は Pages Functions を動かさないため、開発サーバーでは記録されません（エラーにもなりません）。
Functions ごと動かすには、ビルドしてから wrangler を使います。

```bash
npm run build
npx wrangler pages dev out --d1 DB=maro-analytics
```

`STATS_PASSWORD` はプロジェクト直下の `.dev.vars` に書きます（このファイルは Git 管理外です）。

```
STATS_PASSWORD=ローカル確認用のパスワード
```
